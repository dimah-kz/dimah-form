`@dimah-form/ui` is **optional**. `@dimah-form/react` stays headless. The renderer takes a `useFormResponse` return as `form` — it does not call the hook.

Built-in type widgets are not in this package yet. Unknown `type` values render a fallback. Custom types register on `widgets` with the same string as `defineFieldType`.

---

## Install

npm:

```bash
pnpm add @dimah-form/ui @dimah-form/react
```

```css
@import "@dimah-form/ui/styles.css";
```

Or copy source into your app with the shadcn CLI (HTTP registry after docs deploy, or GitHub):

```bash
pnpm dlx shadcn@latest add https://form.dimah.dev/r/form.json
pnpm dlx shadcn@latest add dimah-kz/dimah-form/form
```

---

## Shape

```tsx
import { FormUiProvider, FormView } from "@dimah-form/ui";

const form = useFormResponse({ snapshot });

return (
  <FormUiProvider translations={fa}>
    <FormView form={form} widgets={{ rating: StarRatingField }} />
  </FormUiProvider>
);
```

- `FormView` — chrome (title, visible fields, save, submit). Pass `children` to layout fields yourself.
- `FormField` — label / description / issue around one `form.field(id)` binding.
- `FormUiProvider` — Fuma Translate. Protocol stays on `formClient.Provider`.
- `FieldWidgetRegistry` — `type` → component. Empty for built-ins until those widgets land.

RTL: logical CSS from day one (`text-start`, `ms-*`, `ps-*`). Colors: `*-dimah-form-*` (defaults to your shadcn theme).
