`@dimah-form/ui` is **optional**. `@dimah-form/react` stays headless. The renderer takes a `useFormResponse` return as `form` — it does not call the hook.

Built-in types (`text`, `email`, `date`, `number`, `boolean`, `select`, `multiSelect`) have widgets. Custom `defineFieldType` types register once on `FormUiProvider` with the same `type` string.

---

## Install

npm:

```bash
pnpm add @dimah-form/ui @dimah-form/react
```

```css
@import "@dimah-form/ui/styles.css";
```

Or copy source into your app with the shadcn CLI (HTTP registry after docs deploy, or GitHub):

```bash
pnpm dlx shadcn@latest add https://form.dimah.dev/r/form.json
pnpm dlx shadcn@latest add dimah-kz/dimah-form/form
```

## Template

```tsx
import { FormUiProvider, FormView } from "@dimah-form/ui";

const widgets = { rating: StarRatingField };
const form = useFormResponse({ snapshot });

return (
  <FormUiProvider translations={fa} widgets={widgets}>
    <FormView form={form} />
  </FormUiProvider>
);
```

`FormView` is the default layout: header, progress (hidden when nothing is required), status, visible fields, session error, unsaved/saving hint, save / submit (or Edit when locked). Failed submit focuses the first invalid control. Slot props take `false` to hide or a node to replace (`header`, `progress`, `status`, `error`, `saveState`, `actions`).

Required labels render an asterisk. Pass your own mark once on the provider:

```tsx
function RequiredMark() {
  return (
    <span className="ms-1 text-dimah-form-destructive" aria-hidden>
      required
    </span>
  );
}

<FormUiProvider components={{ RequiredMark }}>
  <FormView form={form} />
</FormUiProvider>;
```

`FormFieldFrame` still hides it with `requiredIndicator={false}`.

## Compose

Every chrome piece is a primitive. `FormScope` provides the session so they do not need a `form` prop:

```tsx
<FormScope form={form}>
  <FormRoot>
    <FormHeader />
    <FormProgress />
    <FormFields />
    <FormSaveState />
    <FormActions />
  </FormRoot>
</FormScope>
```

- `FormField` — looks up the widget for `binding.field.type`. Pass `children` to replace that widget.
- `FormFieldFrame` — label / description / issue chrome. `layout="stack"` (default), `"choice"` (checkbox), or `"group"` (fieldset). Use this when writing a custom widget.
- `FormFields` — maps `visibleFields`. `fields` / `filter` restrict the loop; `meta.section` groups into `FormSection` (or `groupBy={false}` to opt out). `renderField` keeps the loop and swaps chrome per field.
- `FormProgress` / `FormSaveState` / `FormReview` — completion, dirty draft, read-only answers.
- `FormSteps` — groups `meta.step` (number or string, default `"1"`). `FormStepFields` + `FormStepNav` (Next waits until the step’s required fields are answered; last step renders `children`, usually `FormActions`).
- Built-in widgets (`TextField`, `BooleanField`, …) are usable on their own: `<EmailField binding={form.field("email")} />`.

A widget receives `{ binding, className }` — not a spread `FormFieldBinding`. Presentation stays on `meta`:

| Key                | Effect                       |
| ------------------ | ---------------------------- |
| `multiline`        | `text` → textarea            |
| `placeholder`      | input placeholder            |
| `widget: "radio"`  | `select` → radio group       |
| `widget: "switch"` | `boolean` → switch           |
| `widget: "chips"`  | `multiSelect` → toggle group |
| `section`          | heading in `FormFields`      |
| `step`             | page in `FormSteps`          |

RTL: logical CSS from day one (`text-start`, `ms-*`, `ps-*`). Colors: `*-dimah-form-*` (defaults to your shadcn theme).
