Paths and payloads live in `@dimah-form/core`. Default prefix: `/api/form`.

Client methods are on `createFormClient()`. Server methods are `form.api.*` and take `{ query }` or `{ body }`, plus optional `headers` for `guard`.

List endpoints default to 50 rows and cap at 100.

## Forms

| Method | Path           | Client                                    | `form.api`             |
| ------ | -------------- | ----------------------------------------- | ---------------------- |
| `GET`  | `/form`        | `getForm({ formId })`                     | `getForm({ query })`   |
| `POST` | `/form`        | `saveForm(form)`                          | `saveForm({ body })`   |
| `POST` | `/form/delete` | `deleteForm({ formId })`                  | `deleteForm({ body })` |
| `GET`  | `/forms`       | `listForms({ status?, limit?, offset? })` | `listForms({ query })` |

`formId` is an id or a slug.
`saveForm` and `deleteForm` reject code-authored forms (`CODE_AUTHORED_FORM`).
`deleteForm` also rejects a form that still has responses (`FORM_HAS_RESPONSES`).
`listForms` returns `{ forms, limit, offset, nextOffset }`.

## Responses

| Method | Path                | Client                                                                                                                       | `form.api`                  |
| ------ | ------------------- | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| `POST` | `/response/start`   | `startResponse({ formId, respondentId?, resume? })`                                                                          | `startResponse({ body })`   |
| `GET`  | `/response`         | `getResponse({ responseId })`                                                                                                | `getResponse({ query })`    |
| `GET`  | `/responses`        | `listResponses({ formId?, respondentId?, status?, submittedFrom?, submittedTo?, updatedAfter?, include?, limit?, offset? })` | `listResponses({ query })`  |
| `POST` | `/response/draft`   | `saveDraft({ responseId, answers, updatedAt? })`                                                                             | `saveDraft({ body })`       |
| `POST` | `/response/submit`  | `submitResponse({ responseId, answers?, updatedAt? })`                                                                       | `submitResponse({ body })`  |
| `POST` | `/response/abandon` | `abandonResponse({ responseId, updatedAt? })`                                                                                | `abandonResponse({ body })` |
| `POST` | `/response/reopen`  | `reopenResponse({ responseId, updatedAt? })`                                                                                 | `reopenResponse({ body })`  |
| `POST` | `/response/delete`  | `deleteResponse({ responseId })`                                                                                             | `deleteResponse({ body })`  |

`listResponses` returns summaries unless `include` is `"full"`. `total` is the matching count, not the page size.
`submittedFrom` / `submittedTo` are inclusive and skip rows with no `submittedAt`. `updatedAfter` is an exclusive lower bound on `updatedAt`.

## Payloads

`startResponse` freezes the definition and seeds `defaultValue`. `resume: true` needs `respondentId` and returns the latest draft when one exists.

`saveDraft` and `submitResponse` send a partial `answers` object. `null` deletes that key. Send `updatedAt` from the last read — a mismatch is `409 STALE_UPDATE`.

`submitResponse` evaluates `showWhen`, drops hidden answers, then checks every visible field. Success sets `status: "submitted"` and `submittedAt`.

The success body is a [`ResponseRecord`](/docs/responses#stored-record), except
list routes, which return a page.

Plugin routes are not in this table. Scoring, dataset, and insights document their own paths.
