A form is a questionnaire document: `title`, `fields`, and optional `slug`,
`status`, `description`, and `meta`. The key under `forms` is the form id.

```ts title="lib/form.ts"
import { defineForm, dimahForm, memoryAdapter } from "@dimah-form/server";

export const form = dimahForm({
  database: memoryAdapter(),
  forms: {
    feedback: defineForm({
      title: "Feedback",
      slug: "feedback",
      status: "active",
      description: "How was this?",
      fields: [
        { id: "name", type: "text", required: true, label: "Name" },
        { id: "ok", type: "boolean", required: true, label: "I agree" },
      ],
    }),
  },
});
```

Duplicate field ids throw. Unknown field types are allowed in `defineForm`
and rejected at `dimahForm()` if they are not registered. Built-ins and
extras: [Field types](/docs/field-types).

`defineForm` does **not** take `fieldTypes`. The instance is the registry.

## Status and slug

| Field    | Default     | Notes                                                                 |
| -------- | ----------- | --------------------------------------------------------------------- |
| `status` | `"active"`  | `draft` \| `active` \| `archived`. Only `active` forms can be started |
| `slug`   | the form id | Unique. `getForm` and `startResponse` accept id or slug               |

`saveForm` rejects a slug that collides with another form (`SLUG_TAKEN`).
Snapshots always include `slug` and `status` after normalize.

---

## Code-authored vs stored

Forms in config feed TypeScript inference (`form.$Infer`). The live catalog
is read on each get/start — it is not copied at init.

| Operation       | Behavior                                                                                                    |
| --------------- | ----------------------------------------------------------------------------------------------------------- |
| `getForm`       | Config first (id, then slug), then `database.getForm`                                                       |
| `startResponse` | Same resolution. Copies the live definition onto the response                                               |
| `listForms`     | Code-authored first, then stored rows whose ids are not already present                                     |
| `saveForm`      | Upserts the live questionnaire. Cannot overwrite a code-authored id (`CODE_AUTHORED_FORM`)                  |
| `deleteForm`    | Refuses code-authored ids and forms that still have responses (`FORM_HAS_RESPONSES`). Archive with `status` |

Starting a response never overwrites the live definition.

Code-authored forms produce `form.$Infer.answers[formKey]`. Required
fields are required keys; optional fields are omitted keys — the same
object `parseAnswers` returns on submit.

```ts
type Feedback = Form["$Infer"]["answers"]["feedback"];
// { name: string; ok: boolean }
```

Dynamic questionnaires omit `forms` (or mix both). Stored documents do
not feed `$Infer` unless you also keep a type-level catalog.

---

## Meta

Optional `meta` on the form, field, and option documents is an opaque JSON
object for your UI — layout, helper copy, widget hints. The engine does
not read it.

Type-specific keys stay on the field document (`minLength`, `options`,
`min`). Optional `metaSchema.form` / `field` / `option` on `dimahForm()`
validate that bag at init and `saveForm`.

## Calling the catalog

The browser client uses object args. `form.api` uses `{ query }` / `{ body }`.
Full table: [Protocol](/docs/protocol).

```ts
const snapshot = await form.api.getForm({
  query: { formId: "feedback" },
});

await formClient.saveForm({
  id: "nps",
  title: "NPS",
  slug: "nps",
  status: "active",
  fields: [{ id: "score", type: "number", required: true, min: 0, max: 10 }],
});
```

`listForms` returns `{ forms, limit, offset, nextOffset }`. Default
`limit` is 50, max 100. `nextOffset` is `null` when there is no next page.
