[`@dimah-form/scoring`](https://www.npmjs.com/package/@dimah-form/scoring) turns a snapshot into named totals and optional bands.
Scores are derived. They are never written into `answers`, and the plugin adds no tables.

Compute from `response.definition` and the stored answers — not the live questionnaire.

## Install

```npm
npm i @dimah-form/scoring
```

```ts title="lib/form.ts"
import { scoringPlugin } from "@dimah-form/scoring";

export const form = dimahForm({
  database,
  forms,
  plugins: [scoringPlugin()],
});
```

```ts title="lib/form-client.ts"
"use client";

import { scoringClientPlugin } from "@dimah-form/scoring/client";

const plugins = [scoringClientPlugin()] as const;

export const formClient = createFormClient<Form, typeof plugins>({ plugins });
```

The server factory is `@dimah-form/scoring`. The browser companion is `@dimah-form/scoring/client`.

`onScore` runs from `afterSubmit`, after the row is stored. Persist to your database if you need a column. Do not mutate `response.answers`. A throw fails the HTTP response even though the submit is already saved.

```ts
scoringPlugin({
  onScore: async ({ response, scores }) => {
    await db.insert(results).values({
      responseId: response.id,
      payload: scores,
    });
  },
});
```

## Author

Scoring lives in `meta.scoring`. Use `select` (and `meta.widget: "radio"` if you use `@dimah-form/ui`). There is no `likert` field type.

```ts title="lib/forms/gad7.ts"
import { scoringPlugin } from "@dimah-form/scoring";
import { createDefineForm } from "@dimah-form/server";
import type { FormDefinitionUi } from "@dimah-form/ui/types";

const plugins = [scoringPlugin()] as const;
const defineAppForm = createDefineForm({ plugins });

const likert = [
  { value: "0", label: "Not at all", meta: { scoring: { points: 0 } } },
  { value: "1", label: "Several days", meta: { scoring: { points: 1 } } },
  {
    value: "2",
    label: "More than half the days",
    meta: { scoring: { points: 2 } },
  },
  { value: "3", label: "Nearly every day", meta: { scoring: { points: 3 } } },
];

export const gad7 = defineAppForm({
  title: "GAD-7",
  meta: {
    scoring: {
      variables: [{ id: "gad7", label: "GAD-7", min: 0, max: 21 }],
      bands: [
        { variable: "gad7", from: 0, to: 4, label: "Minimal" },
        { variable: "gad7", from: 5, to: 9, label: "Mild" },
        { variable: "gad7", from: 10, to: 14, label: "Moderate" },
        { variable: "gad7", from: 15, to: 21, label: "Severe" },
      ],
    },
  },
  fields: [
    {
      id: "q1",
      type: "select",
      required: true,
      label: "Feeling nervous, anxious, or on edge",
      options: likert,
      meta: { widget: "radio", scoring: { variable: "gad7" } },
    },
  ],
} satisfies FormDefinitionUi<[], typeof plugins>);
```

`createDefineForm({ plugins })` types `meta.scoring`. Forms without that key still load — the schema runs only when the key is present.

If you also have custom field types, pass them to `createDefineForm` and to `FormDefinitionUi<typeof fieldTypes, typeof plugins>`.

### Contributors

| Type          | Likert (`field.variable` + `option.points`) | Keying (`option.add`)      |
| ------------- | ------------------------------------------- | -------------------------- |
| `select`      | Chosen option's points                      | That option's `add` rows   |
| `multiSelect` | Sum of selected points (`[]` is 0)          | Sum of selected `add` rows |
| `number`      | The number                                  | —                          |
| `boolean`     | `true` → 1, `false` → 0                     | —                          |

Hidden `showWhen` fields do not contribute and do not count as missing.

### Option keying

`option.points` adds that number to `field.meta.scoring.variable`.
Use `option.add` when one choice keys one or more variables, and omit `field.meta.scoring`.
Do not mix `points` with `add`, and do not set `field.variable` on a keying item. Reverse scoring does not apply to `add`.

```ts
{
  id: "style",
  type: "select",
  options: [
    {
      value: "parties",
      label: "A crowded party",
      meta: { scoring: { add: [{ variable: "extraversion", points: 2 }] } },
    },
    {
      value: "book",
      label: "A quiet evening",
      meta: { scoring: { add: [{ variable: "introversion", points: 2 }] } },
    },
  ],
}
```

An option with no `meta.scoring` contributes nothing.
An unanswered visible keying item increments `missing` on every variable its options name.

Every `variables[].id` must be referenced by `field.variable` or `option.add`. An unused variable fails `validateDefinition` (`SCORING_UNUSED_VARIABLE`) instead of scoring as `0`.

### Reverse

`reversed = min + max - points`. Set `meta.scoring.reverse: true` on the field.

| Type          | Range                                                                              |
| ------------- | ---------------------------------------------------------------------------------- |
| `select`      | That field's option points. A 0–3 item reverses as `3 - points`, not the scale max |
| `number`      | `field.min ?? 0` through `field.max`. `max` is required                            |
| `boolean`     | `1 - value`                                                                        |
| `multiSelect` | Not supported (`SCORING_REVERSE_MULTISELECT`)                                      |

### Missing items

`variables[].missing` defaults to `"incomplete"`.

| Policy       | Unanswered visible items                                    |
| ------------ | ----------------------------------------------------------- |
| `incomplete` | `raw` is `null`, `complete` is false                        |
| `zero`       | Count as 0                                                  |
| `omit`       | Drop from the sum. `raw` is `null` only when nothing scored |

If every contributing item is hidden, `incomplete` and `omit` are `null`. `zero` is `0`.

### Bands and sums

Bands are labels, not points. `from` / `to` are inclusive. Omit either for an open end. The first match in document order wins.

Sums are `{ id, op: "sum", vars }`. `vars` must be unique variable ids, not other formulas. This is not a formula language.

```ts
formulas: [{ id: "total", op: "sum", vars: ["subscaleA", "subscaleB"] }];
```

## Read

```ts
import { scoreResponse } from "@dimah-form/scoring/client";

const live = scoreResponse(session.snapshot, session.answers);
const stored = await formClient.getResponseScores({ responseId });
const fromApi = await form.api.getResponseScores({ query: { responseId } });
```

Pass the snapshot you are filling, or the stored `response.definition`. Do not fork `useFormResponse` for a live preview.
`scoreResponse` throws on a bad mapping. `collectScoringIssues` returns the issues instead.

```ts
{
  complete: boolean;
  variables: {
    gad7: {
      raw: number | null;
      min?: number;
      max?: number;
      missing: number;
      band?: string;
      complete: boolean;
      label?: string;
    };
  };
}
```

`GET /scoring/response` is the guard operation `getResponseScores`.
Document checks run at `dimahForm()`, `saveForm`, and live form reads. Response snapshots are not re-checked on `getResponse`. `scoreResponse` still validates when you compute.

Codes (`SCORING_UNKNOWN_VARIABLE`, `SCORING_MISSING_POINTS`, `SCORING_OPTION_ADD_MIX`, …) are on [Errors](/docs/errors#scoring).
