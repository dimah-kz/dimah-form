A plugin adds HTTP endpoints, lifecycle hooks, error codes, field types, and `meta` validation.
Persistence stays on `database` — it is not a plugin.

Official plugins: [Scoring](/docs/scoring), [Dataset](/docs/dataset), [Insights](/docs/insights).

## Server

```ts title="lib/plugins/analytics.ts"
import {
  createFormEndpoint,
  defineErrorCodes,
  definePlugin,
  errors,
} from "@dimah-form/server";
import * as z from "zod";

export const ANALYTICS_ERROR_CODES = defineErrorCodes({
  STATS_UNAVAILABLE: "Analytics data could not be computed",
});

export const analyticsPlugin = () =>
  definePlugin({
    id: "analytics",
    $ERROR_CODES: ANALYTICS_ERROR_CODES,
    endpoints: {
      getFormStats: createFormEndpoint(
        "/analytics/stats",
        {
          method: "GET",
          query: z.object({ formId: z.string() }),
        },
        async ({ query, context }) => {
          const form = await context.config.database.getForm(query.formId);
          if (!form) throw errors.unknownForm(query.formId);

          const total = await context.config.database.countResponses({
            formId: query.formId,
          });

          return { formId: query.formId, total };
        },
      ),
    },
    hooks: {
      afterSubmit: async ({ response }) => {
        console.log(`submitted ${response.id}`);
      },
    },
  });
```

```ts title="lib/form.ts"
export const form = dimahForm({
  database: memoryAdapter(),
  forms,
  plugins: [analyticsPlugin()],
});

const stats = await form.api.getFormStats({
  query: { formId: "feedback" },
});
```

`guard` sees the endpoint key as `operation` (`"getFormStats"`). Authorize it like any other admin call. See [Auth](/docs/auth).

## Client

`defineClientPlugin` adds methods on `createFormClient`. It does not infer them from the server instance.
Use the same `id`. If the server plugin registers `fieldTypes`, pass that same array here so local validation matches.

```ts title="lib/plugins/analytics-client.ts"
"use client";

import { defineClientPlugin } from "@dimah-form/react";
import { ANALYTICS_ERROR_CODES } from "./analytics";

export const analyticsClientPlugin = () =>
  defineClientPlugin({
    id: "analytics",
    $ERROR_CODES: ANALYTICS_ERROR_CODES,
    endpoints: ({ $fetch }) => ({
      getStats: (formId: string) =>
        $fetch<{ formId: string; total: number }>(
          `/analytics/stats?formId=${encodeURIComponent(formId)}`,
        ),
    }),
  });
```

```ts title="lib/form-client.ts"
"use client";

import { createFormClient } from "@dimah-form/react";
import type { Form } from "@/lib/form";
import { analyticsClientPlugin } from "@/lib/plugins/analytics-client";

const plugins = [analyticsClientPlugin()] as const;

export const formClient = createFormClient<Form, typeof plugins>({
  basePath: "/api/form",
  plugins,
});

const stats = await formClient.getStats("feedback");
```

The second type argument keeps endpoint names literal.

## meta

Plugin data on a questionnaire lives in `meta`, under a unique `metaNamespace` (`meta.scoring`).
`metaSchema` runs on that nested object only when the key is present, so forms without the plugin still load.
`validateDefinition` is for cross-field rules (unknown ids, mixed keying). It is synchronous and runs at init, `saveForm`, and live form reads — not on response snapshots.
`validateAnswers` checks answer payloads, not the document.

`createDefineForm({ plugins })` types plugin `$Meta`. Share that module with the client plugin.

`dependsOn` orders `init`, hooks, field types, endpoints, `metaSchema`, and validators. Plugin callbacks run first, then `dimahForm({ validateAnswers })` / `validateDefinition` / `metaSchema`.

## Options

| Property             |                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| `id`                 | Unique id. Client ids cannot be `$fetch`, `baseURL`, `$ERROR_CODES`, `$Infer`, or `fieldTypes` |
| `$ERROR_CODES`       | `defineErrorCodes()`. Merged onto `form.$ERROR_CODES`. Cannot shadow core or another plugin    |
| `endpoints`          | `createFormEndpoint` handlers, merged onto `form.api`                                          |
| `hooks`              | Same `on*` / `after*` keys as the instance                                                     |
| `fieldTypes`         | Validators. Mirror them on the client plugin                                                   |
| `metaNamespace`      | Unique `meta` key this plugin owns                                                             |
| `metaSchema`         | Zod for form, field, and option `meta`                                                         |
| `validateDefinition` | Whole-document checks after namespaced `metaSchema`                                            |
| `validateAnswers`    | Extra answer checks after per-field validators                                                 |
| `$Meta`              | Phantom authoring types for `createDefineForm`                                                 |
| `init`               | Sync setup. Return `{ context }` and read it later with `getPluginContext(id)`                 |
| `dependsOn`          | Plugin ids that must load first                                                                |
| `options`            | Closed-over config for sibling plugins                                                         |
