A plugin can add HTTP endpoints, lifecycle hooks, error codes, field types, `meta` validation, answer validators, and matching methods on `createFormClient`.

---

## 1. Creating a Server Plugin

Use `definePlugin()` and `createFormEndpoint()` from `@dimah-form/server` to build a server extension:

```ts title="lib/plugins/analytics-plugin.ts"
import {
  createFormEndpoint,
  defineErrorCodes,
  definePlugin,
  errors,
} from "@dimah-form/server";
import * as z from "zod";

// 1. Declare domain-specific error codes
export const ANALYTICS_ERROR_CODES = defineErrorCodes({
  STATS_UNAVAILABLE: "Analytics data could not be computed",
});

// 2. Define the server plugin
export const analyticsPlugin = () =>
  definePlugin({
    id: "analytics",
    $ERROR_CODES: ANALYTICS_ERROR_CODES,

    // Add custom HTTP endpoints to the dimahForm router
    endpoints: {
      getFormStats: createFormEndpoint(
        "/analytics/stats",
        {
          method: "GET",
          query: z.object({
            formId: z.string(),
          }),
        },
        async ({ query, context }) => {
          const form = await context.config.database.getForm(query.formId);
          if (!form) throw errors.unknownForm(query.formId);

          const list = await context.config.database.listResponses({
            formId: query.formId,
            limit: 100,
          });

          const total = list.length;
          const submitted = list.filter((r) => r.status === "submitted").length;

          return {
            formId: query.formId,
            totalResponses: total,
            completionRate: total > 0 ? (submitted / total) * 100 : 0,
          };
        },
      ),
    },

    // Optional lifecycle hooks contributed by this plugin
    hooks: {
      afterSubmit: async ({ response }) => {
        console.log(`[Analytics] Response ${response.id} submitted.`);
      },
    },
  });
```

## 2. Registering on the Server

Pass the plugin to `dimahForm({ plugins: [...] })`:

```ts title="lib/form.ts"
import { dimahForm, memoryAdapter } from "@dimah-form/server";
import { analyticsPlugin } from "@/lib/plugins/analytics-plugin";
import { forms } from "@/lib/forms";

export const form = dimahForm({
  database: memoryAdapter(),
  forms,
  plugins: [analyticsPlugin()],
});

export type Form = typeof form;
```

You can now call the plugin endpoint directly through `form.api`:

```ts
const stats = await form.api.getFormStats({
  query: { formId: "feedback" },
});
```

## 3. Creating a Companion Client Plugin

To expose typed methods on `createFormClient`, create a companion client plugin using `defineClientPlugin()`:

```ts title="lib/plugins/analytics-client.ts"
import { defineClientPlugin } from "@dimah-form/react";
import { ANALYTICS_ERROR_CODES } from "./analytics-plugin";

export const analyticsClientPlugin = () =>
  defineClientPlugin({
    id: "analytics",
    $ERROR_CODES: ANALYTICS_ERROR_CODES,
    endpoints: ({ $fetch }) => ({
      getStats: (formId: string) =>
        $fetch<{
          formId: string;
          totalResponses: number;
          completionRate: number;
        }>(`/analytics/stats?formId=${encodeURIComponent(formId)}`, {
          method: "GET",
        }),
    }),
  });
```

Register the client plugin with `createFormClient`. If the server plugin
registers `fieldTypes`, list the same array on the client plugin so local
session validation matches. Client plugins may also list `validateAnswers`
and phantom `$Meta` (same types as the server plugin).

```ts title="lib/form-client.ts"
"use client";

import { createFormClient } from "@dimah-form/react";
import type { Form } from "@/lib/form";
import { analyticsClientPlugin } from "@/lib/plugins/analytics-client";

export const formClient = createFormClient<Form>({
  basePath: "/api/form",
  plugins: [analyticsClientPlugin()],
});

// Call the plugin method from client components
const stats = await formClient.getStats("feedback");
```

## 4. Meta, namespaces, and authoring types

Plugin rules that belong on the questionnaire (scores, variables, formulas)
live in the opaque `meta` bag — not as extra keys on the form document.
Own a **namespace** so several plugins can share the same bag next to UI
keys (`widget`, `step`, …):

```ts title="lib/plugins/scoring-plugin.ts"
import {
  definePlugin,
  type NamespacedMeta,
} from "@dimah-form/server";
import * as z from "zod";

type ScoringInner = {
  form: { variables: { id: string; max: number }[] };
  option: { points: number };
};

export const scoringPlugin = () =>
  definePlugin({
    id: "scoring",
    metaNamespace: "scoring",
    $Meta: {} as NamespacedMeta<"scoring", ScoringInner>,
    metaSchema: {
      form: z.object({
        variables: z.array(
          z.object({ id: z.string(), max: z.number() }),
        ),
      }),
      option: z.object({ points: z.number() }),
    },
    validateAnswers: (_definition, _answers, mode) => {
      if (mode !== "submit") return;
      // Read `_definition.meta?.scoring` — same snapshot submit already uses.
    },
  });
```

`metaNamespace` is unique across plugins. `metaSchema` then validates
`meta.scoring` (the inner object) **only when that key is present**, so
forms without the plugin still init. Instance `dimahForm({ metaSchema })`
still runs on the whole bag afterwards.

Author catalogs against the same plugin objects (type-only — same as
`fieldTypes`):

```ts
import { createDefineForm } from "@dimah-form/server";
import type { FormDefinitionUi } from "@dimah-form/ui/types";
import { scoringPlugin } from "@/lib/plugins/scoring-plugin";
import { fieldTypes } from "@/lib/field-types";

const plugins = [scoringPlugin()] as const;
const defineAppForm = createDefineForm({
  fieldTypes,
  plugins,
});

export const quiz = defineAppForm({
  title: "GAD-7",
  meta: { scoring: { variables: [{ id: "gad7", max: 21 }] } },
  fields: [
    {
      id: "q1",
      type: "select",
      options: [{ value: "0", meta: { scoring: { points: 0 } } }],
    },
  ],
} satisfies FormDefinitionUi<typeof fieldTypes, typeof plugins>);
```

`createDefineForm({ plugins })` types the field document and plugin `meta`.
`satisfies FormDefinitionUi<typeof fieldTypes, typeof plugins>` adds UI
`meta` keys. Share the `$Meta` module with the client plugin.

`validateAnswers` on a plugin is chained in `dependsOn` order, then the
instance callback, on both `dimahForm()` and `createFormClient({ plugins })`.

## Plugin Options Reference

| Property              | Type                           | Description                                                                                        |
| :-------------------- | :----------------------------- | :------------------------------------------------------------------------------------------------- |
| **`id`**              | `string`                       | Unique alphanumeric identifier for the plugin.                                                     |
| **`$ERROR_CODES`**    | `ErrorCodeCatalog`             | Custom error codes declared via `defineErrorCodes()`.                                              |
| **`endpoints`**       | `Record<string, FormEndpoint>` | Map of custom route handlers.                                                                      |
| **`hooks`**           | `DimahFormHooks`               | Pre-write and post-write lifecycle hooks.                                                          |
| **`fieldTypes`**      | `FieldTypeDefinition[]`        | Custom field validators (server and matching client plugin).                                       |
| **`metaNamespace`**   | `string`                       | Unique `meta` key this plugin owns (`meta.scoring`).                                               |
| **`metaSchema`**      | `FormDefinitionMetaSchema`     | Zod checks for form / field / option `meta`. Namespaced bags run only when the key is present.     |
| **`validateAnswers`** | `AnswersValidator`             | Extra answer checks after per-field validators. Chained, then the instance callback.               |
| **`$Meta`**           | `FormDefinitionMeta`           | Phantom authoring types. Prefer `NamespacedMeta`. Used by `createDefineForm` / `FormDefinitionUi`. |
| **`init`**            | `(ctx) => { context? }`        | Sync setup. Receives `basePath`, `fieldTypes`, `plugins`, `getPluginContext`.                      |
| **`dependsOn`**       | `string[]`                     | Array of required plugin IDs that must be loaded before this plugin.                               |
