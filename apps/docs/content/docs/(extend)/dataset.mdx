[`@dimah-form/dataset`](https://www.npmjs.com/package/@dimah-form/dataset) exports stored responses as `dimah.dataset/v1`.
One record per response, a codebook of the snapshots those responses actually used, and optional CSV.

Use it when a warehouse file must stay honest after the live form changes.
Live counts are [Insights](/docs/insights). This plugin is not a dashboard.

Records come from the response snapshot, never the live questionnaire. The plugin adds no tables and no `meta` namespace. The canonical file is JSON Lines plus a codebook. HTTP stays paged (limit max 100). Zip the full export in your app.

## Install

```npm
npm i @dimah-form/dataset
```

```ts title="lib/form.ts"
import { datasetPlugin } from "@dimah-form/dataset";

export const form = dimahForm({
  database,
  forms,
  plugins: [
    datasetPlugin({
      onProject: async ({ record }) => {
        await warehouse.upsert(record.id, record);
      },
    }),
  ],
});
```

```ts title="lib/form-client.ts"
"use client";

import { datasetClientPlugin } from "@dimah-form/dataset/client";

const plugins = [datasetClientPlugin()] as const;
export const formClient = createFormClient<Form, typeof plugins>({ plugins });
```

The package depends on `@dimah-form/scoring`. `getDatasetPage` attaches `scoreResponse` when the snapshot has `meta.scoring`. A scoring error on one historical row omits `scores`. Any other error propagates. Scores are not written into `answers`.

Guard operations: `getDatasetPage`, `getDatasetCodebook`, `getLiveCodebook`. Treat them like `listResponses`.

## Codebooks

| Call                      | Describes                                                                                                                           |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `getLiveCodebook`         | The live questionnaire, in live field order. `snapshots[0].n` is 0 and there is no seen-at. Do not join this to old answers         |
| `getDatasetCodebook`      | Union of snapshots in the filtered set. Canonical fields follow `lastSeenAt`. An older snapshot that differs is one `history` entry |
| `getDatasetPage` codebook | This page only. Merge with `mergeCodebooks` / `createDatasetReader` if you page yourself. `mergeCodebooks` keeps `history`          |

`formatted` on each field is English `formatAnswer`. Select labels in the codebook and in `responses.labels.csv` keep the author's copy. Pass `booleanLabels` on encode when Yes/No must not be English.

## Spec

Every JSON object carries `spec: "dimah.dataset/v1"`.

**Record.** No raw `definition`. Identity: `id`, `formId`, `status`, `submittedAt`, `createdAt`, `updatedAt`, `snapshotKey`. `snapshotKey` is SHA-256 of the instrument under [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785) (`title`, `description`, `fields`, `meta` — not `id`, `slug`, `status`, or timestamps). HTTP includes `respondentId`. Package encode omits it unless `includeRespondentId: true`. `fields` is dense: every snapshot field, unanswered as `value: null`. `attachment` is set only for `file` (`id`, `url`, `name`, `contentType`, `size`). No inline bytes. Optional `scores` matches `scoreResponse`.

**Codebook.** Newest `lastSeenAt` wins the canonical field (label, type, `required`, `description`, `showWhen`, constraints, options, scoring). Each older snapshot whose view differs gets one `history` object with that view and its `snapshotKey` — not one row per response. Join `record.snapshotKey` to canonical `inSnapshots` or to `history`.

Scoring columns come from `readScoringFormMeta` / `readScoringFieldMeta` in `@dimah-form/scoring/document`. A bad variable, band, or formula row is skipped. A field may carry `scoring.variable` and `scoring.reverse`. Options carry `points` or `add`, never both — an invalid mix is omitted. `scores.variables[]` includes `missing` (`zero`, `omit`, `incomplete`) when the form sets it. Omitted means the scoring default, `incomplete`. `scores.formulas[]` is `{ id, op: "sum", vars }` plus optional `label`. Variables, bands, and formulas get `history` when their definition differs.

## HTTP

Same list window as core: default 50, max 100. The plugin passes `limit + 1` into the store. Default `status` is `submitted`. Filters match `listResponses`: `respondentId`, inclusive `submittedFrom` / `submittedTo`, exclusive `updatedAfter`. Each page includes `total` for the filter, not the page size.

| Method | Path                        | Operation            |                                                                                                                                                   |
| ------ | --------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/dataset/responses`        | `getDatasetPage`     | `formId` required. `{ spec, records, codebook, limit, offset, nextOffset, total }`                                                                |
| `GET`  | `/dataset/codebook/history` | `getDatasetCodebook` | Historical codebook. Walks on the server, default cap 10_000. Query `maxRows` can lower that cap, not raise it. `truncated` when more rows remain |
| `GET`  | `/dataset/codebook`         | `getLiveCodebook`    | Codebook of the live form                                                                                                                         |

```ts
const page = await form.api.getDatasetPage({
  query: { formId: "gad7", limit: 100 },
});
const history = await form.api.getDatasetCodebook({
  query: { formId: "gad7" },
});
```

Filename, zip, and timeout stay in your app.

## Full file

CSV columns need a complete codebook first (`getDatasetCodebook` or `reader.readCodebook()`). If `truncated` is true, do not encode a full CSV — raise `datasetPlugin({ maxRows })` or persist with `onProject`.

`readCodebook()` returns `{ codebook, total, truncated }`. `readAll()` buffers every page and has no `truncated` flag — use it for a small N. JSONL does not need the historical codebook.

```ts
import { createCsvEncoder, createDatasetReader } from "@dimah-form/dataset";

const history = await form.api.getDatasetCodebook({ query: { formId } });
const encoder = createCsvEncoder(history.codebook);
const reader = createDatasetReader({
  page: ({ limit, offset }) =>
    form.api.getDatasetPage({ query: { formId, limit, offset } }),
  codebook: async () => history,
});

const chunks = [encoder.header()];
for await (const record of reader.records()) {
  chunks.push(encoder.row(record));
}
```

```ts
import {
  createDatasetReader,
  toCsv,
  toDataPackage,
  toJsonl,
} from "@dimah-form/dataset";

const { records, codebook } = await createDatasetReader({
  page: ({ limit, offset }) =>
    form.api.getDatasetPage({ query: { formId, limit, offset } }),
}).readAll();

const jsonl = toJsonl(records);
const csv = toCsv(records, codebook, {
  fields: ["score_item"],
  omit: ["respondentId"],
});
const files = toDataPackage(records, codebook);
```

`toDataPackage` returns a filename → contents map (`datapackage.json`, `codebook.json`, `responses.jsonl`, `responses.csv`, `responses.labels.csv`). It is not a zip. `datapackage.json` uses the Frictionless tabular profile. `responses.csv` sets `missingValues: [""]`, `primaryKey: ["id"]`, dialect (`quoteChar`, `doubleQuote`, `\r\n`), and codebook constraints (`enum`, `minimum` / `maximum`, `required`). JSONL stays nested. `responses.labels.csv` is display text (UTF-8 BOM only there) and has the same dialect, not a schema.

CSV is RFC 4180. `multiSelect` joins with `;`. Object answers stringify as JSON in the codes CSV. Column order: identity (including `updatedAt`), field columns (historical codebooks sort ids), then `score.<id>.raw` / `.band` / `.complete` / `.missing`. `.missing` is the unanswered item count.

A field id that matches an identity column, or starts with `score.`, is written as `field.<id>`. If a field is also literally `field.<id>`, encoding throws. `fields` is still a list of field ids. `omit` drops output column names.

Pass a live codebook when you want live form order.

## onProject

Same timing as scoring `onScore`: `afterSubmit`, after persist. Upsert by `record.id` — `reopenResponse` then submit runs the hook again. A throw fails the HTTP response after the row is stored.

## Out of this package

SPSS, Parquet, FHIR, attachment bytes, `meta.dataset`, charts ([Insights](/docs/insights)), and zip inside `dimahForm()`.
