`startResponse` copies the live form into `response.definition`.
Drafts, `showWhen`, and submit all use that copy. They do not read the live questionnaire.

<Callout>
  Editing the live form does not change an in-flight draft or a submitted row.
</Callout>

## Status

| Status      | Meaning                                | Next calls                                        |
| ----------- | -------------------------------------- | ------------------------------------------------- |
| `draft`     | Required fields may be empty           | `saveDraft`, `submitResponse`, `abandonResponse`  |
| `submitted` | Visible required fields passed. Locked | `reopenResponse`, `deleteResponse`, `getResponse` |
| `abandoned` | Closed without submit. Locked          | `reopenResponse`, `deleteResponse`, `getResponse` |

`saveDraft` or `submitResponse` on a locked row is `409 RESPONSE_NOT_DRAFT`.
`reopenResponse` on a draft is `409 RESPONSE_NOT_LOCKED`.

## Lifecycle

| Call              | What it does                                                                                                                                          |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `startResponse`   | Active forms only. Freezes `definition`, seeds `defaultValue`. `{ resume: true, respondentId }` returns the latest draft instead of inserting another |
| `saveDraft`       | Partial patch. `null` deletes that answer key. Required fields may be empty                                                                           |
| `submitResponse`  | Strips hidden fields, checks every visible field, sets `submitted` and `submittedAt`                                                                  |
| `abandonResponse` | Sets `abandoned` and locks edits                                                                                                                      |
| `reopenResponse`  | `submitted` or `abandoned` → `draft`. Keeps the original snapshot and answers                                                                         |

`resume: true` without `respondentId` is `400 RESUME_REQUIRES_RESPONDENT`.

## Compare-and-swap

`saveDraft` and `submitResponse` send the `updatedAt` from the last read.

The store writes only when that token still matches. A mismatch is `409 STALE_UPDATE` — another tab saved first.
`useFormResponse` refreshes on `STALE_UPDATE`.

Omit `updatedAt` only when you intend to overwrite.

## Record

```ts
type ResponseRecord = {
  id: string;
  formId: string;
  status: "draft" | "submitted" | "abandoned";
  definition: FormSnapshot;
  answers: Record<string, unknown>;
  respondentId: string | null;
  submittedAt: string | null;
  createdAt: string;
  updatedAt: string;
};
```

Set `respondentId` in `onStart`. Do not trust a value sent by the browser. See [Auth](/docs/auth).
