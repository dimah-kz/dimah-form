These helpers are defined in `@dimah-form/core` and re-exported from
`@dimah-form/react`. They do not render UI.

```ts
import {
  fieldLabel,
  fieldOptions,
  formErrorMessage,
  isFieldVisible,
  issuesByField,
  visibleFields,
} from "@dimah-form/react";
```

## Labels, options, and visibility

```ts
fieldLabel(field); // label, or the field id
fieldOptions(field); // { value, label, meta? }[] for select / multiSelect
visibleFields(snapshot, answers); // fields whose showWhen matches
isFieldVisible(field, answers);
```

`useFormResponse` already exposes `visibleFields` and `field(id).error`.
Use these helpers when you call the protocol client directly or build a
widget map.

---

## Errors

```ts
issuesByField(issues); // { [fieldId]: message }
formErrorMessage(error, "Request failed");
```

`issuesByField` accepts `{ field, message }[]` or an `APIError`.
`formErrorMessage` returns the English `APIError.message`, else
`Error.message`, else the fallback.

---

## Answers

```ts
import {
  applyAnswerPatch,
  collectAnswerIssues,
  parseAnswers,
  seedDefaultAnswers,
  stripHiddenAnswers,
} from "@dimah-form/react";
```

| Helper                | Role                                                        |
| --------------------- | ----------------------------------------------------------- |
| `applyAnswerPatch`    | Merge a draft patch. `null` / `undefined` deletes a key     |
| `stripHiddenAnswers`  | Drop keys hidden by `showWhen`                              |
| `seedDefaultAnswers`  | Start payload from `defaultValue`, then strip hidden        |
| `collectAnswerIssues` | `{ field, message }[]` for `"draft"` or `"submit"`          |
| `parseAnswers`        | Strip, validate, drop empty keys. Throws `VALIDATION_ERROR` |

Submit validation against a snapshot belongs on the server. These helpers
are for local checks and for stores that speak the same protocol.
