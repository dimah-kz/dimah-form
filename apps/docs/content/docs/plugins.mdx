Use `definePlugin` for additive features: endpoints, hooks, field types,
and `$ERROR_CODES`. Persistence stays on `database` — plugins do not add
tables.

```ts title="lib/ping-plugin.ts"
import {
  createFormEndpoint,
  defineErrorCodes,
  definePlugin,
} from "@dimah-form/server";

export const ping = (options?: { token?: string }) =>
  definePlugin({
    id: "ping",
    options,
    $ERROR_CODES: defineErrorCodes({ PING_FAILED: "Ping failed" }),
    endpoints: {
      ping: createFormEndpoint("/ping", { method: "GET" }, async () => ({
        ok: true,
      })),
    },
  });
```

```ts title="lib/form.ts"
import { dimahForm, memoryAdapter } from "@dimah-form/server";
import { ping } from "./ping-plugin";

export const form = dimahForm({
  database: memoryAdapter(),
  plugins: [ping()], // [!code ++]
});

await form.api.ping({});
```

Prefer a factory that closes over options and returns `definePlugin`.
`options` is for sibling plugins to read; keep your own config in the
closure.

## Endpoints

`createFormEndpoint` paths are absolute under `basePath`. Zod `body` /
`query` failures throw `VALIDATION_ERROR`.

Guard `operation` is the `endpoints` key (`"ping"`) unless
`metadata.operation` is set:

```ts
ping: createFormEndpoint(
  "/ping",
  { method: "GET", metadata: { operation: "health" } },
  async () => ({ ok: true }),
);
```

Plugin routes cannot shadow core names or paths.

## Init and context

`init` runs once in `dimahForm()`, after plugins are sorted. It must be
synchronous. Return `{ context }` for request handlers.

```ts
import {
  createFormEndpoint,
  definePlugin,
  getPluginContext,
} from "@dimah-form/server";

const a = definePlugin({
  id: "a",
  options: { n: 1 },
  init({ options }) {
    return { context: { n: (options as { n: number }).n } };
  },
});

const b = definePlugin({
  id: "b",
  dependsOn: ["a"],
  endpoints: {
    peek: createFormEndpoint("/peek", { method: "GET" }, async (ctx) => ({
      a: getPluginContext<{ n: number }>(ctx.context.config, "a"),
    })),
  },
});
```

`dependsOn` is a topological order for `init`, hooks, field types, and
endpoints. Missing deps, cycles, and duplicate `id` throw.

## Client companion

Browser plugins are not inferred from the server plugin. Share `id` and
the error catalog module. Register them on `createFormClient({ plugins })`.

```ts
import { defineClientPlugin, defineErrorCodes } from "@dimah-form/react";

const PING_ERROR_CODES = defineErrorCodes({ PING_FAILED: "Ping failed" });

export const pingClient = () =>
  defineClientPlugin({
    id: "ping",
    $ERROR_CODES: PING_ERROR_CODES,
    endpoints: ({ $fetch }) => ({
      ping: () => $fetch<{ ok: true }>("/ping", { method: "GET" }),
    }),
  });
```

```ts
export const formClient = createFormClient<Form>({
  plugins: [pingClient()], // [!code ++]
});

await formClient.ping();
```

## Frequently asked questions

<Accordions>

<Accordion title="Can a plugin replace memoryAdapter or db()?">

No. Pass a `ResponseStore` to `dimahForm({ database })`. Plugins are
additive features only.

</Accordion>

<Accordion title="How are hooks ordered?">

Plugin `on*` / `after*` run first (`dependsOn`, then registration order),
then instance hooks.

</Accordion>
