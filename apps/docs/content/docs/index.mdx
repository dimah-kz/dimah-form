dimah-form is a questionnaire engine for React and Node.js.
It freezes the form onto every response, validates answers against that snapshot, and gives React a headless fill session.
Rendering is yours, or optional `@dimah-form/ui`.

A fill starts from the live form, then keeps that definition.
Later edits do not change in-flight drafts or submitted rows.

## What you get

- **Snapshots** — submit checks the definition taken at start
- **Drafts** — partial saves with `updatedAt` compare-and-swap
- **Headless client** — `useFormResponse` and field bindings
- **Optional UI** — shadcn renderer on the same session
- **Server hooks** — auth in `guard`, ownership and side effects in `on*` / `after*`
- **Optional SQL** — `memoryAdapter()`, or `@dimah-form/db` when rows must survive a restart

It is not a visual builder or a hosted survey product.

## Packages

| Package                | Role                                               |
| ---------------------- | -------------------------------------------------- |
| `@dimah-form/server`   | `dimahForm()` — HTTP handler, `form.api`, adapters |
| `@dimah-form/react`    | `createFormClient()`, `useFormResponse()`          |
| `@dimah-form/ui`       | Optional shadcn renderer                           |
| `@dimah-form/db`       | Optional SQL adapter (FumaDB)                      |
| `@dimah-form/scoring`  | Optional scores from the snapshot (`meta.scoring`) |
| `@dimah-form/dataset`  | Optional JSONL + codebook export                   |
| `@dimah-form/insights` | Optional read-side summaries                       |
| `@dimah-form/core`     | Protocol. Apps import `server` or `react` instead  |

`database` is required. A SQL database is not.

## Frequently asked questions

<Accordions>

<Accordion title="When should I choose dimah-form?">

When the questionnaire is part of your app: typed definitions, drafts, and server-side submit checks, with your own UI or `@dimah-form/ui`.

Skip it for a drag-and-drop builder or a hosted survey.

</Accordion>

<Accordion title="Does dimah-form render inputs?">

`@dimah-form/react` does not. Bind `q.field(id)` yourself, or add [`@dimah-form/ui`](/docs/ui).

</Accordion>

<Accordion title="Where does authentication live?">

In your `guard`. The library does not ship sessions. See [Auth](/docs/auth).

</Accordion>

<Accordion title="Can someone still submit after the form changes?">

Yes. Drafts and submits use `response.definition`, the snapshot stored at start. See [Snapshots](/docs/snapshots).

</Accordion>

</Accordions>
