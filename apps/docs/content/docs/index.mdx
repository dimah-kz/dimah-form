dimah-form is a modular questionnaire engine for React and Node.js runtimes.
It owns the protocol, definition snapshots, drafts, and submit validation.
You own rendering, auth, and the database adapter.

## Architecture flow

The browser talks through `createFormClient`. The server instance
(`dimahForm()`) validates answers against the snapshot stored on the
response — not the live questionnaire.

## What you get

- **Typed protocol** — one schema in `@dimah-form/core`, used by server and React
- **Snapshots** — each response keeps the definition it was started with
- **Drafts and submit** — patch drafts, replace on submit, optional reopen
- **Headless React** — `useFormResponse` binds your widgets; it is not a renderer
- **Persistence** — `memoryAdapter()` to try the protocol, or FumaDB via `@dimah-form/db`

Custom fields are `defineFieldType` validators, not components. There is
no form renderer and no shadcn registry.

## Packages

| Package              | Role                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------- |
| `@dimah-form/server` | `dimahForm()`, HTTP `handler`, `form.api`, adapters                                   |
| `@dimah-form/react`  | `createFormClient`, `useFormResponse` — no widgets                                    |
| `@dimah-form/db`     | FumaDB `database` adapter (`db()`)                                                    |
| `@dimah-form/core`   | Protocol SSOT. App code imports `server` or `react`; shared field types import `core` |

```
@dimah-form/core
        ↓
@dimah-form/server | @dimah-form/react
        ↑
@dimah-form/db   (peer of server)
```

`database` is required: `memoryAdapter()` from server, or `db()` from
`@dimah-form/db`. Custom stores implement `ResponseStore`.

Share types with `export type Form = typeof form` and
`createFormClient<Form>()`. Do not pass the server instance into the browser.

## Frequently asked questions

<Accordions>

<Accordion title="When should I choose dimah-form?">

When you need typed questionnaires with drafts, definition snapshots, and
submit validation, and you already have (or want) your own field widgets.

Skip it if you want a ready-made form renderer, a visual builder, or a
hosted survey product.

</Accordion>

<Accordion title="Does dimah-form ship field widgets?">

No. Built-in field types are validators (`text`, `number`, `boolean`,
`select`, `multiSelect`, `email`, `date`). Extra types are
`defineFieldType`. Rendering stays in your app.

</Accordion>

<Accordion title="Where does auth live?">

In your `guard` on `dimahForm()`. Throw `APIError` with a catalog code —
a plain `Error` becomes `INTERNAL_ERROR`. See [Auth](/docs/auth).

</Accordion>

<Accordion title="Is the database optional?">

No. `database` is required. Use `memoryAdapter()` from
`@dimah-form/server` for tests or ephemeral apps, or `db()` from
`@dimah-form/db` for FumaDB persistence.

</Accordion>

<Accordion title="How do I share types between server and React?">

`export type Form = typeof form` on the server instance, then
`createFormClient<Form>()` in the browser. Pass the same `fieldTypes`
array on both sides when you have extras.

</Accordion>

</Accordions>
